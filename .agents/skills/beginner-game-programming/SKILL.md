# 按实际工程实现游戏

读取 `AGENTS.md`、项目概念、当前操作卡、功能任务和 `02_工作流规范/游戏类型与技术适配.md`。检查真正的工程路径、版本、依赖、源码和 Git 状态，不能把工作流网页当游戏工程。

## 技术路线

- 已有工程先沿用；新项目按目标平台、玩法、2D/3D、运行与资源工具能力选择，记录理由、限制和最小运行验证。只有会改变客户已确认体验、预算或迁移已有成果时才提出选择，不让新手替 AI 决定架构。
- Unity 2D 读取包内 [Unity 2D 专项](../beginner-unity-2d/SKILL.md)；其他路线如宿主确实有适用技能则读取，否则依据当前版本官方资料执行。不要声称调用了未安装的插件，也不要为了匹配 skill 把已有工程换成 Unity。
- Unity 核对 ProjectVersion、Packages 和 Assets；Unreal 核对 uproject、引擎版本和模块/插件；Godot 核对 project.godot；Cocos/浏览器项目核对对应项目配置、依赖与启动脚本。路径只在实际检查后写入操作卡。

## 实现与接入

从本次玩家可观察结果追踪输入、状态所有者、规则、表现、失败和清理，沿用已有结构，只做当前所需改动。按玩法检查重复执行、中断恢复与资源生命周期；随机、异步、物理或联网只在实际使用时处理相关风险。

交接写明真实文件/资产、对象或节点、组件/脚本、字段和连接、操作与预期画面。能可靠装配就自行完成；需客户操作时给少量已核对步骤。3D 模型、碰撞、动画、镜头或网络连接均需真实接入，不用图片或文档代替。

## 验证

按实际改动执行静态检查、自动测试、编译及开发环境交互运行；发布阶段构建/装配交付产物，再在目标环境独立运行。兼容证据键 editor/build/player 的含义见类型适配规范，不能用网页工具测试或早期版本结果验收新游戏。

完成正确性和单独必要性审查，修复并复测，记录命令或步骤、版本、日志和未覆盖项。缺工具时继续可完成工作，给可执行运行步骤并保留待验证；不得因此降低阶段最低门槛。按当前操作卡、资源生产及交付维护规范同步实际任务和证据。
