# 新手多类型游戏开发工作流 · V0.4-pilot.1

供少量使用者试用的 Windows 本地工作流。通过 Codex 引导完成游戏的需求、设计、制作、测试、交付和维护；适配动作、解谜、叙事、经营、策略/卡牌、审核等玩法与混合类型。此包不是已做好的游戏，也不会离线自动调用 AI。

## 第一次使用

GitHub 使用者请下载 [V0.4-pilot.1 干净试用包](https://github.com/rainerpj/beginner-game-dev-workflow/raw/refs/heads/master/交付包/游戏开发工作流_V0.4-pilot.1.zip)。此 ZIP 已准备好空白项目记录；仓库的 Code → Download ZIP 是含开发与验证历史的源码副本，首次试用请使用前面的专用包。

1. 完整解压 ZIP，保留隐藏的 `.agents`。用 Codex 打开能看到 AGENTS.md 的那层文件夹。需要自己的可用 Codex 账户和本地文件读写能力。
2. 将已有设定发给 Codex 或放入 `00_客户资料/`。说：**“请先读我的资料和 AGENTS.md，按工作流带我开始。我没有游戏开发经验；沿用已确定的方向，只问现在必须决定的缺口。”** 没有资料也可以从想法开始。
3. 双击 `启动进度网页.cmd`，按首页的第一步说明继续。网页需要 Python 3.10+；没有时先让 Codex 帮助检查。网页不需要 Git、Node、额外 Python 包或 API Key。

网页只显示记录和收集本地反馈。点击“继续这一步”后，将文字粘贴到 Codex；反馈保存后也需要让 Codex 读取。所有游戏任务起始未验收。游戏引擎和资源工具由 AI 按实际项目选择，不预设 Unity 2D。

先读 [小范围试用说明](01_客户指南/10_小范围试用说明.md)，卡住时读 [第一次打不开怎么办](01_客户指南/07_第一次打不开怎么办.md)。包内已初始化，不需要再次初始化。

## 试用边界

先尝试体量可控的项目。其他引擎可按真实工程适配，但不代表所有技术工具已随包安装，也不代表所有游戏类型都经过实际开发验证。AI 账户、软件、付费资源及后续支持不包含在包内。

区分文档、自动测试、开发环境运行、游戏构建、目标设备和客户体验。未完成完整内容、测试及交付验收，不把原型标为完整游戏。模型和工具可能出错，当前版本仍需真实使用反馈。

新游戏用独立目录。已有项目升级先备份，再合并工具差异；不要用空白项目记录覆盖旧进度。网页导出不是完整备份，复制整个项目时保留素材、工程、证据及改进备份。

未自动发送资料、购买资源、上传、提交 Git 或发布游戏。所有对外操作按客户实际授权处理。

## 维护与构建

源码仓库：[beginner-game-dev-workflow](https://github.com/rainerpj/beginner-game-dev-workflow)。维护者可运行 `python 04_本地进度网页/build_pilot.py --help` 查看打包选项。打包器生成独立初始记录，不覆盖现有 ZIP 或客户进度；修改后的包需重新验证，不能沿用旧包的测试结论。
