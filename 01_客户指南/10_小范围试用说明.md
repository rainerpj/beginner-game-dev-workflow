# 小范围试用说明 · V0.4-pilot.1

这是用于收集早期使用反馈的游戏开发工作流，适合先尝试体量可控的单人游戏。支持多种玩法的设计与制作引导；尚未证明零经验使用者能靠它独立完成所有类型的游戏。它不是游戏引擎，也不是离线自动制作游戏的软件。

## 开始前需要什么

- 一台 Windows 电脑，以及能打开本地文件夹、读取/修改文件的 Codex 环境和你自己的可用账户。先确认能发送消息并读取此目录；不同客户端界面可能不同，按实际版本操作。
- 网页需要 Python 3.10 或更新版本。没有时先用 Codex 读取本目录并协助安装或选择现有解释器；不要自己猜命令。网页仅使用 Python 标准库，不需要 Node、Git、额外 Python 包或 API Key。
- 游戏引擎、图像/音频工具按具体项目检查。缺引擎可以先讨论设计；缺资源工具可以先用占位验证，不能把占位说成正式资产。账户、付费资源和工具费用不包含在包内。

本轮在 Windows 本机检查过解压、启动、网页、状态工具和跨类型合成项目流程；没有在全新客户电脑安装验证，没有完成真实新手长期试用，也没有完成各引擎游戏的运行或发行验证。其他操作系统不是本轮试用验证范围。

## 第一次只做一个小闭环

1. 把 ZIP 完整解压到一个固定、可写的本地文件夹，保留 `.agents`，不要直接在压缩包预览里运行。用 Codex 打开包含 AGENTS.md 的那层文件夹。
2. 将已有资料发给 Codex 或放入 `00_客户资料/`，说：“先读我的资料和项目工作流，检查环境，再带我开始。没有资料的部分从具体玩家场景问我。”
3. 双击启动脚本，按首页说明保存一条真实反馈，再让 Codex 读取并答复。做到这一步就可以反馈首次试用感受，不必先做完一个游戏。

每款游戏使用独立目录。已经在使用旧包时先完整备份，再让 AI 合并工具差异；不要把这个新包的空白 `项目记录/` 覆盖旧进度。包内已经初始化，不需要再运行初始化脚本。

## 哪里卡住了，怎样反馈

直接在当前 Codex 对话说：“我在【哪一步】做了【什么】，实际看到【什么】，不知道接下来怎么做。”可以保存到网页“我的反馈”，然后回到 Codex 让它读取。网页不会自动把消息发送给模型或包的提供者。

需要联系把包发给你的人时，把版本号 V0.4-pilot.1、卡住的一步、报错原文和预期结果发给对方即可。截图只截相关区域；不必发送整个项目、私有设定或账户信息。是否提供进一步支持，由你与提供者约定，包内没有在线客服或自动上传渠道。

反馈优先关注：第一次能否打开；AI 有没有读资料、重复问已确定的事；给出的下一步能否照做；错误后是否能继续；是否误把文档完成说成游戏已运行。无需填写专业测试表。

## 记录和恢复

文件保存在当前目录；浏览器的未提交草稿只在当前浏览器。关键节点备份整个目录，网页导出只是进度副本。使用中请保留原项目，不通过删除记录或重装模板解决问题。AI 卡住时让它更新 `docs/CODEX_HANDOFF.md`，换对话后从交接继续。
