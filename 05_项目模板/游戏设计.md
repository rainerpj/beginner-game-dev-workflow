# 游戏设计

规则由已有资料、客户决定和实际验证形成；模板及参考作品不是已批准需求。

## 一次典型游玩

填写：玩家目标 → 看见的信息 → 输入/动作 → 规则处理 → 成功、失败或中断反馈 → 后续变化与再次行动。先推演一例正常和一例受阻情境。

## 玩法与边界

填写：允许的动作、前置条件、状态和数据所有者、规则优先级、数值/时间/随机性（若适用）、重复操作、暂停/退出、重试和恢复。按类型适配规范补充实际相关的碰撞、解法、资源、回合或判定等细节；混合玩法写清状态如何衔接。

## 内容发展与完成条件

填写内容单位、引入新机制的顺序、难度/成长和完整体验标准。关卡型写全关卡与解锁，对局型写开局至结算再开局，持续游玩型写目标与保存/重返闭环。有叙事时补触发、人物动机、选择记忆、后果和分支收束；无叙事不强加剧情结局。数量只引用完整版本范围。

## 产品体验

约定开始/继续、教学、设置、退出、输入、可读性、声音及适用的存档、暂停和恢复。功能不适用时记录依据，不能省去已承诺项或阶段验证。

## 决定与实验

每条规则附决定或实验 ID，区分 `[Confirmed]`、`[Proposal]`、`[To Decide]`、`[To Prototype]`。体验假设经验证后再更新，不把研究结论当本游戏运行结果。
