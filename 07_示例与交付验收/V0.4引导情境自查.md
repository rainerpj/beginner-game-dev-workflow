# V0.4 引导情境自查

日期：2026-11-18。执行者：本轮 Codex，同一 AI 依据重新读取后的 skills、类型适配规范、模板、提示词和阶段配置进行推演；不是独立代理测试、真人访谈或实际游戏开发。

| 输入情境 | 按新流程得出的下一步与验收关注点 | 结论 |
|---|---|---|
| “就是原来的 Papers, Please 那种，我已有港口设定” | 先读港口资料，沿用审核方向；选案件/规则/工作日内容单位，核对重复判决与后果；不重问类型 | 原方向仍可用，不把通用化变成重新立项 |
| “我想做横版跳跃，有现成 Unity 2D 工程，跳起来太飘” | 先核对工程与现有输入、碰撞和动作；程序入口转 Unity 2D 专项，从起跳、落地和重试观察手感，不增加证件或剧情任务 | 类型与程序路线匹配 |
| “Godot 解谜，机关顺序有几种，已有设计文档” | 读取设计和 project.godot；推演不同顺序、死锁与重置，保留 Godot；没有专项工具也不假装已运行，给真实入口后待验证 | 已有引擎保留，规则能转为可测用例 |
| “经营小店，没有结局，想一直经营” | 约定资源链、时间推进、经营里程碑、退出保存及重返闭环；以已承诺内容和稳定持续游玩验收，不强加剧情结局 | 无固定结局不免除完整验收 |
| “做卡牌战斗，赢得材料后回家建造” | 卡牌回合和建造资源分别拆规则，再验证胜利奖励只入账一次、库存与建造消耗衔接；只采纳两类相关检查 | 混合玩法有交界验证，不堆全部类型清单 |
| “不知道类型，只想轻松探索，看风景” | 先读现有图片与想法；从一段探索体验给少量差异选项，未决定视角/平台时按当前依赖提问，暂不安装引擎或承诺规模 | 未定类型可开始，不强制套标签 |
| “已有 Unreal 第三人称工程，想改角色动画” | 核对 uproject、引擎版本、资产和现有动画链；使用实际可用能力，模型/骨骼/动画与碰撞在工程接入后验证；不转 Unity | 3D 与已选技术路线得到保留 |
| “浏览器益智游戏，开发网页能玩了，交付吧” | editor 只记录开发运行；仍要装配可交付产物并在约定浏览器独立运行，再验完整内容和客户体验 | 证据类别未因无编辑器而降级 |
| “想做大型联网开放世界” | 先说明同步、服务、内容量、设备和维护风险，用小范围技术样本验证最高风险，再由客户决定可承担的完整范围 | 通用流程不承诺任意规模自动实现 |

正确性复查发现并修正：首轮仍有资料接收规范中的“审核场景”、交付版本模板中的 Unity 字样，以及范围/故事提示词中的固定剧情和审核表述；最终改为当前玩家场景、实际引擎和约定完成条件。审核对话及证件美术例子保留为明确示例；历史报告不改写。

单独必要性复查：采用一份类型适配规范和一个通用程序入口，继续使用现有设计/范围文件与唯一 state.json，不新增类型数据库、引擎切换界面或平行进度。project 操作仅解决通用项目展示名称/方向此前无法受校验更新的问题；不改验收规则。完整生命周期、已有证据保护、客户决定和对外授权均保留。

限制：这些结果证明当前规则在所列情境下可一致解释，不证明后续模型每次执行都遵守，也不证明任何引擎游戏已实现。I1 只进入试用，须等待后续真实项目使用证据。
